# Кейс 4. Интерфейсы структур данных и тесты GoogleTest

Проект содержит только интерфейсы и тесты по заданию: алгоритмы структур данных и фабрики не реализованы. Функции `make_queue`, `make_heap`, `make_binary_search_tree` объявлены, но не определены. Поэтому запустить поведенческие тесты без предоставленной отдельно реализации невозможно. Сборка по умолчанию компилирует только объектный файл с тестами; это проверка синтаксиса, а не проверка поведения.

## Допущения о контракте

- Все значения имеют тип `int`; каждая фабрика возвращает непустой указатель на новый пустой объект.
- `Queue::push` добавляет элемент, `pop` извлекает его по FIFO и возвращает `std::nullopt` при пустой очереди. Дубликаты сохраняются.
- `Heap` — минимальная куча: `pop` извлекает минимальное значение, `std::nullopt` означает пустую кучу; дубликаты сохраняются.
- `BinarySearchTree` — двоичное дерево поиска с уникальными ключами. `push` повторного ключа ничего не меняет, `search` возвращает признак наличия, `pop(key)` удаляет указанный ключ и возвращает `true` при успешном удалении, `false` если ключ отсутствовал. В частности, в задачах о листе и узлах с одним или двумя потомками предполагается обычная BST, в которую значения вставлены в указанном порядке без автоматической балансировки. Внутренний способ удаления и вид результирующего дерева не проверяются.

## Сборка и запуск

Требуются CMake 3.20+, компилятор с поддержкой C++17 и GoogleTest 1.14 или новее. CMake сначала ищет установленный пакет GTest подходящей версии; при отсутствии скачивает версию 1.14.0 с GitHub (нужно сетевое соединение). В среде с установленным пакетом можно указать `-DCMAKE_PREFIX_PATH=путь_к_пакету`.

```sh
cmake -S case4_cpp -B case4_cpp/build -DCMAKE_BUILD_TYPE=Debug
cmake --build case4_cpp/build --config Debug
```

Эти команды выполняют **только компиляцию** тестов. Чтобы связать и запускать их, разработчик должен отдельно предоставить исходный C++ файл, реализующий все интерфейсы и три фабрики; заголовок доступен как `#include "structures.hpp"`. Полный абсолютный путь передаётся в CMake:

```sh
cmake -S case4_cpp -B case4_cpp/build-run -DCASE4_IMPLEMENTATION=/absolute/path/implementation.cpp
cmake --build case4_cpp/build-run --config Debug
ctest --test-dir case4_cpp/build-run -C Debug --output-on-failure
```

В Windows вместо примера укажите существующий путь вида `C:/path/implementation.cpp`. Если реализация распределена по нескольким файлам, соберите их в библиотеку или адаптируйте CMake. Двойники в проект не включены. Результат тестирования имеет смысл только для реально подключённой реализации.

## Сценарии

Написаны 14 тестов GoogleTest: четыре для очереди (пустое состояние, один элемент, FIFO с повторами, чередование операций), четыре для min-heap (пустое состояние, один элемент, порядок с отрицательными и повторяющимися значениями, чередование операций) и шесть для BST (пустое состояние, поиск, удаление листа, узла с одним и двумя потомками, дубликаты и повторное добавление).
